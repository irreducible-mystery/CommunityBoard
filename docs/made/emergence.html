Emergence, with the rules showing.

A grid of cells, a handful of states, and a few lines of rules that each cell follows using only its neighbours. Nothing in the rules mentions clusters, gliders, fronts or spirals. Pick a preset, edit any line, press Apply, and watch what the change does. Apply keeps the seed, so the only difference is the one you made.

How to write rules

One instruction per line. # starts a comment, and the first comment line is the title.

states dead alive          2 to 10 names, the first is 0
colours #000 #fd0          optional
neighbourhood moore        or vonneumann (4 neighbours)
edges wrap                 or wall
update sync                or async (one cell at a time, random order)
noise 0.001                chance per cell per step of a random state
size 96 72                 width height, 4 to 400
start dead 0.7 alive 0.3   initial mix (fractions)
seed anything

Become rules: from -> to if condition. For each cell, the first rule whose from matches and whose condition is true wins. No condition means always.

Swap rules move things, so counts are conserved: sand swap empty S SE|SW tries to swap with an empty cell to the south, otherwise south-east or south-west at random. Use anywhere to swap with a random cell of that state anywhere on the grid, or nearby for any neighbour.

Conditions: a state name means how many neighbours are in that state. You also have neighbours (how many there are), random (0 to 1), t (the step), N is alive or SE is wall for one direction (N NE E SE S SW W NW), the operators + - * / %, == != < <= > >=, and and or not with brackets.

dead -> alive if alive == 3
alive -> dead if alive < 2 or alive > 3
tree -> fire if fire > 0 or random < 0.00002
red swap empty anywhere if red < 0.3 * (red + blue)

Nothing here is ever run as code. The text is parsed into a small fixed set of operations.

Self-checks

  
On load the page checks the engine against facts that are known independently: a blinker has period 2, a glider crosses a 16 by 16 torus in 64 steps, swaps conserve counts, a bad rule is refused, and so on.

  
    

    

    


    Emergence v1 · works offline, no network, no eval. Randomness is seeded (mulberry32), so a seed plus the rule text reproduces a run exactly in the same browser. Clumping measures how much more often neighbouring cells share a state than they would if the same counts were shuffled: 0 means well mixed, 1 means every neighbour matches. Activity is the share of cells that changed in the last step. Cycle detection compares whole-grid hashes and only runs when the rules have no randomness in them.
